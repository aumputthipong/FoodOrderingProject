## 3. พื้นฐานที่ใช้ร่วมกัน

### 3.1 Token และ component พื้นฐาน (GLOB-1, GLOB-2, GLOB-4, MF-1)
- **สีปุ่มรอง:** ปุ่ม `outline` ใช้ `border bg-card shadow-xs hover:bg-muted hover:text-foreground` และ `ghost` ใช้ `hover:bg-muted hover:text-foreground` ส่วน `--accent` (เหลืองไข่) ใช้กับป้ายสถานะเท่านั้น
- **Focus ring:**
  - ใน base layer ของ `main.css` ให้ทุก `a`, `button`, `input`, `textarea`, `[role=tab|switch|checkbox|radio]` ที่อยู่ในสถานะ `:focus-visible` มี `outline: 2px solid var(--ring); outline-offset: 2px`
  - ปุ่มพื้น primary ใช้ outline สี `--foreground`
  - ต้องเห็นชัดทั้งบนพื้นขาว พื้นเทา และพื้นส้ม
- **ช่องกรอก:** `Input` และ `Textarea` ใช้ `bg-card`
- **Token ตัวอักษรและความโค้ง** ใน `@theme`:
  - ตัวอักษร: `--text-caption: 13px`, `--text-body-sm: 15px`, `--text-title: 20px`, `--text-display: 26px`
  - ความโค้ง: `--radius-card: 16px`, `--radius-thumb: 10px`
- **หัวข้อหน้า:** ใช้รูปแบบเดียวกันทุกหน้า คือ `font-heading text-title` ฝั่งลูกค้า และ `text-display` ฝั่งแม่ค้า
- **แทนค่าเดิม:** ค่า `text-[13px]`/`[15px]`/`[22px]`/`[26px]` และความโค้งที่ตั้งเอง ให้เปลี่ยนไปใช้ token ในทุกไฟล์ที่แตะ

### 3.2 ข้อความ validation (GLOB-6)
- `toFormSchema` แปลง issue ต่อไปนี้เป็น 'กรุณากรอกข้อมูลนี้':
  - `invalid_type` ที่ input เป็น `undefined`
  - `too_small` ของ string ที่ `minimum` เป็น 1
- ช่อง `price` ใช้ 'กรุณากรอกราคา'
- ข้อความ custom เดิมยังแปลตามตารางเดิม

### 3.3 หน้าว่างและหน้า error (GLOB-5)
- **`EmptyState`:** props `{ title: string; description?: string; icon?: Component }` ไอคอนอยู่ในวงกลม `size-14 rounded-full bg-accent/25 text-primary` และมี slot `action`
- **`ErrorState`:** มีไอคอน `CircleAlert` คู่กับข้อความเสมอ
- **ทุกจุดที่เรียกใช้มีคำอธิบายและปุ่ม:**

| ที่ | title | description | action |
|---|---|---|---|
| ค้นหาไม่เจอ | ไม่พบร้านที่ค้นหา | ลองค้นด้วยชื่อร้านอื่น | ล้างคำค้นหา |
| ไม่มีร้าน | ยังไม่มีร้านในโรงอาหาร | – | – |
| ร้านไม่มีเมนู | ร้านนี้ยังไม่มีเมนู | ลองดูร้านอื่นก่อนนะ | ดูร้านทั้งหมด |
| ตะกร้าว่าง | ตะกร้ายังว่าง | เลือกเมนูจากร้านในโรงอาหารได้เลย | ไปเลือกร้าน |
| คิว กำลังทำ ว่าง | ยังไม่มีคิวที่กำลังทำ | สั่งอาหารแล้วคิวจะแสดงที่นี่ | ไปเลือกร้าน |
| คิว เสร็จแล้ว ว่าง | ยังไม่มีคิวที่เสร็จ | – | – |
| แม่ค้า ไม่มีออเดอร์ | ยังไม่มีออเดอร์ | ออเดอร์ใหม่จะแสดงที่นี่อัตโนมัติ | – |
| แม่ค้า เสร็จแล้ว ว่าง | ยังไม่มีออเดอร์ที่เสร็จ | – | – |
| แม่ค้า ไม่มีเมนู | ยังไม่มีเมนู | เพิ่มเมนูแรกของร้านได้เลย | เพิ่มเมนู |

- **Not Found:** แสดงบัตรคิวเล็ก "#404" และรับ props `title`/`actionLabel`/`actionTo` เพื่อให้หน้าร้านใช้ 'ไม่พบร้านนี้' คู่กับ 'ดูร้านทั้งหมด'

### 3.4 Motion (GLOB-3), เฉพาะที่ให้ feedback หรือบอกสถานะ
หลักการ (เจ้าของ repo กำหนด): ไม่ใส่ animation ตกแต่ง และไม่ใส่ animation ที่เสี่ยงทำให้เกิดบั๊ก (เช่นมีผลกับ DOM, timing หรือ layout ระหว่างเล่น) จึงไม่มีการเลื่อนหรือจางตอนปรากฏ ไม่ใช้ `<Transition>`/`<TransitionGroup>` และไม่มี scale ตอนกด ใช้ได้เฉพาะ CSS transition ของสีและความกว้างแถบความคืบหน้า
- **hover และ focus:** control ที่เปลี่ยนสีตอน hover/focus ใช้ `transition-colors` (บางจุดมีอยู่แล้ว)
- **ตอนกด:** ปุ่ม primary, ปุ่ม +/−, แถบตะกร้า และปุ่มสั่งใช้สีเข้มขึ้นตอน `active:` (เช่น `active:bg-primary/80` หรือสี hover ที่เข้มกว่า) แทนการ scale
- **แถบความคืบหน้าของบัตรคิว:** `motion-safe:transition-[width] motion-safe:duration-500`
- **toast และ popup:** ใช้ animation มาตรฐานของ vue-sonner และ reka-ui ตามเดิม ไม่เพิ่มเอง
- **ตัดออกจากผลตรวจ:** animation ตอนเปลี่ยนหน้า, แถบตะกร้าเลื่อนขึ้น, การ์ด scale, ตัวเลขเด้ง, บัตรใหม่เลื่อนเข้า, TransitionGroup ของคิวแม่ค้า

### 3.5 เมนูที่หมด (SHOP-2, MM-1)
- **เลิกใช้ `opacity-60` ทั้งการ์ด** แล้วใช้หน้าตานี้แทน:
  - รูปเป็น `grayscale`
  - ชื่อเป็น `text-muted-foreground`
  - ป้าย 'หมดชั่วคราว' เป็น `bg-foreground/80 text-background`
- **ใช้ที่:** `MenuItemCard` (ลูกค้า) และแถวใน `MenuPage` (แม่ค้า)
- **คำอธิบายเมนู:** ต้องผ่าน contrast AA

### 3.6 ความกว้างบนจอคอม (T4)
- หน้าเนื้อหาฝั่งลูกค้า (ตะกร้า, คิว, บัญชี) ใช้ `md:max-w-3xl md:mx-auto`
- หน้าที่เป็น grid (หน้าแรก, หน้าร้าน) ใช้ `max-w-5xl`

## 4. ฝั่งลูกค้า

### 4.1 หน้าแรก (HOME-1, HOME-2, HOME-3, HOME-4, GLOB-7)
- **banner:**
  - เปลี่ยนวงกลมเหลืองเป็นบัตรคิวเล็ก "#12" (`rotate-6 rounded-xl bg-accent px-3 py-2 font-heading` พร้อมเส้นปรุ)
  - บนจอ `md:` ใช้ `p-8` และหัวข้อ `text-3xl`
  - ซ่อนตอนมีคำค้นหา
- **รูปร้าน:** `ImageWithFallback` รับ prop `class` เพิ่ม `ShopCard` บนมือถือใช้รูปจัตุรัส 76px ส่วน `md:` ใช้ 16:10
- **ช่องค้นหา:** ตาม `route.query.q` เวลากด back/forward
- **query ร้าน:** ใช้ `placeholderData: keepPreviousData` ไม่ให้ Skeleton ขึ้นซ้ำทุกครั้งที่ค้นหา
- **Skeleton:** ขนาดและรูปร่างเท่าการ์ดจริงทั้งมือถือและคอม

### 4.2 หน้าร้าน (SHOP-1, SHOP-3, SHOP-4, SHOP-5, SHOP-6, SHOP-7)
- **รูปปกบนจอ `md:`:** สูงไม่เกิน 288px (`md:h-72 md:overflow-hidden md:rounded-b-3xl`) และรูปใช้ `object-cover` เต็มกล่อง
- **แถบตะกร้า:**
  - บนจอ `md:` เป็นกล่องลอยกว้าง 384px มุมขวาล่าง (`md:inset-x-auto md:right-8 md:w-96`)
  - ป้ายจำนวนไม่ทับข้อความ
- **ข้อความในการ์ดเมนู:** ชื่อและคำอธิบายใช้ `line-clamp-2`
- **id ร้านผิดหรือ API ตอบ 404:** แสดง Not Found 'ไม่พบร้านนี้' พร้อมปุ่ม 'ดูร้านทั้งหมด'

### 4.3 ตะกร้า (CART-2, CART-3)
- **ปุ่มสั่งตอนกำลังส่ง:** แสดง 'กำลังสั่ง…' พร้อม `Loader2 animate-spin`
- **หลังสั่งสำเร็จ:** ไม่แสดง EmptyState จนกว่าจะเปลี่ยนหน้า (ใช้ flag `ordered`)
- **บนจอ `md:`:** ใช้ 2 คอลัมน์เฉพาะตอนมีมากกว่าหนึ่งตะกร้า

### 4.4 คิวของฉันและบัตรคิว (ORD-1, ORD-2, ORD-3, ORD-5)
- **แถบความคืบหน้า:** พื้นราง `bg-muted` ให้มองเห็นตอน 0%
- **บัตรที่เสร็จแล้ว:** มีแถบ `bg-success/10 text-success` ข้อความ '✓ พร้อมรับที่ร้าน' และขอบ `ring-2 ring-success/40`
- **รอยเว้าข้างบัตร:** `h-7 w-3.5`
- **Tabs บนจอ `md:`:** กว้าง `w-80`
- **ข้อความตอนว่าง:** แยกตามแท็บ (ตารางข้อ 3.3)

### 4.5 บัญชี (ACC-1, ACC-2)
- ทั้งหน้ามี padding `p-4 md:pt-8` และอยู่ในความกว้างตามข้อ 3.6
- หัวข้อ 'บัญชีของฉัน' อยู่นอกการ์ด ตัวการ์ดเป็น `rounded-card` ไม่มีขอบและเงา
- มีวงกลมตัวอักษรแรกของชื่อ พื้น `bg-accent`
- ปุ่ม 'ออกจากระบบ' เป็น ghost สีแดง (`text-destructive`)

### 4.6 แถบนำทาง (NAV-1, NAV-2)
- **TopNav:**
  - แสดงชื่อผู้ใช้เป็นป้ายกดได้ไปหน้า `account`
  - เอาปุ่มออกจากระบบออก (ออกจากระบบทำที่หน้าบัญชี)
- **BottomNav:**
  - ป้ายจำนวน 18px ตัวอักษร 11px ตาม mockup
  - แท็บที่เลือกอยู่มีขีดด้านบนหนา 2px สี primary ไม่ใช้สีอย่างเดียวบอกสถานะ

### 4.7 Login และ AuthLayout (AUTH-1, AUTH-2)
- โลโก้กดกลับหน้าแรกได้ และมีลิงก์ '← กลับไปเลือกร้าน'
- ถ้ามี `?redirect=` แสดงข้อความ 'เข้าสู่ระบบเพื่อสั่งอาหาร' ใต้หัวข้อ
- **กล่องบัญชีทดลอง:**
  - แสดงเมื่อ `import.meta.env.VITE_DEMO_HINT === 'true'`
  - ข้อความ 'บัญชีทดลอง: customer1 (ลูกค้า) · merchant1 (ร้านค้า) · รหัสผ่าน Password123'
  - ประกาศ type ไว้ใน `env.d.ts`
  - Dockerfile ของ web รับ build arg `VITE_DEMO_HINT` (ค่าเริ่มต้นว่าง)

## 5. ฝั่งแม่ค้า

### 5.1 Layout (MER-1, MER-2, MER-3, MER-4)
- **padding:** เหลือที่ layout ชั้นเดียว หน้าแม่ค้าทั้ง 5 หน้าเอา padding ของตัวเองออก
- **ลิงก์ 'ไปหน้าลูกค้า':** ย้ายเข้าไปใน sidebar และในแถบแท็บบนจอต่ำกว่า `lg` ไม่มีแถวแยกอีกแล้ว
- **รูปร้านใน sidebar:** ส่ง `shop.imageUrl` ไปให้ `ImageWithFallback` แสดงรูปจริง
- **ลิงก์ 'เมนูในร้าน':** แสดงเป็นหน้าที่เลือกอยู่ตอนเปิด `merchant-menu`, `merchant-menu-new` และ `merchant-menu-edit` โดยดูจากชื่อ route

### 5.2 จัดการคิว (MQ-1, MQ-2, MQ-3, MQ-4, MQ-5)
- **เลขคิว:** `text-[44px]` ตั้งเป็น token `--text-ticket`
- **ป้าย 'รอ x นาที':**
  - คำนวณจาก `createdAt` ในฟังก์ชัน `waitMinutes(createdAt, now)` ใน `lib/format.ts`
  - อัปเดตทุก 30 วินาทีด้วย `useNow` จาก `@vueuse/core`
  - เกิน 10 นาทีเป็นป้าย `bg-accent` ไม่เกินเป็นสีเทา
  - ต่ำกว่า 1 นาทีแสดง 'เพิ่งสั่ง'
- **รายการอาหาร:** ตัวอักษร `text-base` และ checkbox ใหญ่ `size-6`
- **เบอร์โทร:** `formatMobile('0900000001')` ได้ '090-000-0001' ถ้าค่าที่ได้ไม่ใช่ตัวเลข 10 หลัก ให้คืนค่าเดิม
- **กด 'เสร็จทั้งออเดอร์' สำเร็จ:**
  - แสดง `toast.success('คิว #<id> เสร็จแล้ว')` พร้อม action 'ย้อนกลับ'
  - action เรียก mutation เปลี่ยนสถานะกลับเป็น `waiting` ตัวเดิม
- **คอลัมน์ 'เสร็จแล้ว' ตอนว่าง:** ใช้ EmptyState ตามตารางข้อ 3.3

### 5.3 เมนู (MM-1, MM-2, MM-3)
- **เมนูที่หมด:** ใช้หน้าตาตามข้อ 3.5
- **ป้ายข้างสวิตช์:** เปลี่ยนตามสถานะเป็น 'เปิดขาย' หรือ 'หมดชั่วคราว'
- **สวิตช์:** ขนาด `h-6 w-11` แก้ที่ `ui/switch` ให้เป็นขนาดปกติ
- **ปุ่ม 'แก้ไข':** เป็นปุ่ม outline มีไอคอน `Pencil`
- **ความกว้างรายการ:** `max-w-3xl`

### 5.4 ฟอร์มร้านและเมนู (MF-1, MF-2, MF-3)
- **การ์ดฟอร์ม:** อยู่ในการ์ด `rounded-card border bg-card p-6`
- **`ImageUploadField`:**
  - กล่องรูปกว้างไม่เกิน `max-w-56` และเป็น `<label for>` ที่กดเลือกรูปได้ทั้งกล่อง มี hover และ focus ring
  - ข้อความแนะนำและข้อความ error มี `id` และผูกกับ input ด้วย `aria-describedby` ส่วน `aria-invalid` ตั้งเมื่อมี error
  - ข้อความ error เก่าหายเมื่อ `modelValue` ถูกตั้งเป็น `null` จากภายนอก
- **ปุ่มยกเลิกและกลับ:**
  - มีปุ่มกลับ (`ChevronLeft`) ด้านบนและปุ่ม outline 'ยกเลิก' ข้างปุ่มบันทึก
  - ฟอร์มเมนูกลับไป `merchant-menu` ส่วนฟอร์มแก้ร้านกลับไป `merchant-queue`
  - หน้าสร้างร้านไม่มีปุ่มยกเลิก

## 6. Testing

- **test เดิม:** ต้องผ่านทั้งหมด ถ้า test เดิมเช็ค class หรือข้อความที่เปลี่ยน ให้แก้ test ตาม spec นี้
- **test ใหม่ (อย่างน้อย):**
  - `toFormSchema`: ช่องว่างได้ 'กรุณากรอกข้อมูลนี้' และราคาว่างได้ 'กรุณากรอกราคา'
  - `formatMobile` และ `waitMinutes`: ขอบที่ 0 นาที, 1 นาที, 10 นาที, 11 นาที และ input ที่ไม่ถูกต้อง
  - `EmptyState` และ `ErrorState`: แสดงไอคอน คำอธิบาย และ action
  - หน้าแรก: กด back แล้วช่องค้นหากลับเป็นค่าเดิม, ปุ่ม 'ล้างคำค้นหา' ล้าง `?q=`
  - Login: มี `?redirect=` แล้วเห็นข้อความ 'เข้าสู่ระบบเพื่อสั่งอาหาร', กล่องบัญชีทดลองแสดงเฉพาะเมื่อตั้ง env
  - คิวแม่ค้า: toast 'คิว #x เสร็จแล้ว' และกด 'ย้อนกลับ' แล้วส่ง status `waiting`, ป้ายรอเกิน 10 นาทีเป็นสี accent
  - ลิงก์ 'เมนูในร้าน' active ตอนอยู่หน้าแก้เมนู
  - `ImageUploadField`: มี `aria-describedby` และ `aria-invalid`, error เก่าหายเมื่อ reset
- **Contrast:**
  - คำนวณและบันทึกค่า contrast ของสีใหม่ทั้งหมดในรายงาน
  - ตัวอักษรต้อง ≥ 4.5:1 และ focus ring กับ control ต้อง ≥ 3:1 บนพื้นขาว เทา และส้ม
