# Roadmap: Canteen Ordering ฉบับ Portfolio

- **วันที่:** 2026-10-22
- **สถานะ:** อนุมัติแล้ว

## เป้าหมาย

ปรับโปรเจกต์สมัยเรียนปี 2 (Vue 2 + Express + MySQL) ให้เป็นผลงาน portfolio สายงาน **Fullstack** ที่ทันสมัย

สิ่งที่ port ต้องแสดงให้เห็น:
- การตัดสินใจเชิงโครงสร้างที่อธิบายเหตุผลได้
- โค้ดที่มี test, type และ CI ยืนยันความถูกต้อง
- ระบบที่รันได้ด้วยคำสั่งเดียวและมี live demo
- ฟีเจอร์ realtime ที่แก้ปัญหาจริงของโรงอาหาร

## Stack ที่ตัดสินใจแล้ว

| ส่วน | เลือก |
|---|---|
| ภาษา | TypeScript (strict) ทั้งระบบ |
| โครงสร้าง repo | Monorepo: pnpm workspaces (`apps/api`, `apps/web`, `packages/shared`) |
| Frontend | Vue 3 (`<script setup>`) + Vite + Vue Router 4 + Pinia |
| UI | Tailwind CSS + shadcn-vue |
| Backend | Express 5 จัดโฟลเดอร์ตามฟีเจอร์ (`modules/*`) |
| Validation / contract | Zod ใน `packages/shared` ใช้ร่วมกันทั้ง API และฟอร์ม |
| Database | MySQL 8.4 + Drizzle ORM + migrations |
| Realtime | Socket.IO + event bus (เฟส 3) |
| Test | Vitest + supertest (API), Vue Test Utils (web) |
| คุณภาพโค้ด | ESLint + Prettier + type check |
| Infra | Docker Compose, GitHub Actions CI, OpenAPI / Swagger UI |

ทางเลือกที่พิจารณาแล้วไม่เลือก:
- **React / Next.js:** เลือกอยู่กับ Vue แล้วเน้นเรื่อง structure
- **NestJS:** เลือก Express 5 เพื่อวาง architecture เองและอธิบายได้ทุกชั้น
- **Bulma:** เปลี่ยนเป็น Tailwind เพราะต้องเขียน UI ใหม่ทั้งหมดอยู่แล้ว

## หลักการทำงาน

1. **แยก refactor ออกจากฟีเจอร์ใหม่:** เฟส 1–2 ต้องคงพฤติกรรมเดิม (ยกเว้นการแก้บั๊ก) ฟีเจอร์ใหม่เริ่มที่เฟส 3 ถ้ามีอะไรพังจะได้รู้ว่าพังเพราะอะไร
2. **ทุกเฟส:** spec → review → implementation plan → ลงมือทีละ task → ตรวจรับ
3. **Branch:**
   - งานทั้งหมดอยู่บน `refactor/architecture`
   - ติด tag `v1-legacy` ไว้ที่ `master` เดิมก่อน merge
   - merge เข้า `master` หลังจบเฟส 2 (ตอนที่ระบบใช้งานได้ครบอีกครั้ง)
4. **ไม่ push หรือลบ branch บน GitHub** จนกว่าเจ้าของ repo จะสั่ง
